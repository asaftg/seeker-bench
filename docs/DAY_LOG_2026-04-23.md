## 2. Radar overlay on EO + thermal panels

Projection-only augmentation (NOT late fusion): radar targets are
rendered on the EO and thermal panels as cyan dashed bboxes.

- **Pipeline:** `(pos_x_m, pos_y_m, pos_z_m)` → `(az, el)` →
  `angular_to_bbox()` into each panel's pixel grid.
- **Where:** new `_radar_target_to_panel_bboxes()` helper in
  `gui/sensor_bridge.py`; each wire-format target gains `bbox_thermal`
  and `bbox_eo`.
- **Client:** `thermal_view.js` and `eo_view.js` pick up a
  `radarTargets` kwarg in `update()`, draw via `drawRadarBox` from
  `overlays.js`. Coasting targets render at alpha 0.55 with `· coast`
  label suffix.
- **Gating:** surfaced via the unified OVERLAY SCREEN card (see §4).

**Terminology note:** this is display/projection augmentation, not
track-to-track fusion. Fused tracks still come exclusively from the
EO↔thermal `FusionManager`. A true radar-fused path (producing unified
FusedTrack IDs with radar as a contributing sensor) is Phase 2.

## 3. Software extrinsic calibration — vs. EO ground truth

Mount is rigid, so we're fixing misalignment in software. Added
`az_bias_deg` + `el_bias_deg` offsets for both radar and thermal,
applied before projection. EO stays unbiased as ground truth.

**Files**
- `config/app_config.yaml` — `radar.extrinsic`, `thermal.extrinsic`
  blocks (both default 0.0)
- `radar/radar_manager.py` — ctor accepts bias kwargs, `set_extrinsic()`,
  `get_tuning()` echoes them
- `fusion/fusion_manager.py` — reads `thermal.extrinsic` at boot,
  applies bias to the thermal→(az,el) conversion inside
  `_observations_from_thermal()` under a lock. EO obs path untouched.
  `set_extrinsic()` + `get_extrinsic()` for live tuning.
- `gui/app.py` — passes radar bias into `build_ws_message`, adds
  `payload["extrinsic"]` to every tick, handles new `extrinsic_tune`
  WS command
- `gui/sensor_bridge.py` — bias applied inside
  `_radar_target_to_panel_bboxes`
- `gui/static/index.html` — new "EXTRINSIC CALIBRATION · vs. EO"
  DEV-tab card, 4 sliders (-10° to +10°, step 0.1)
- `gui/static/js/main.js` — debounced `extrinsic_tune` IIFE,
  hydrates from server payload on first tick

**Tuning flow:** drag a slider in DEV tab → 80ms debounce → WS command
→ manager `set_extrinsic()` → next frame renders with bias applied.
No restart needed. Persisting to YAML is still manual (edit the file).

## 4. Unified OVERLAY SCREEN card (source-centric toggles)

Replaced two separate DEV-tab cards (FUSION OVERLAYS + RADAR OVERLAYS)
with a single **OVERLAY SCREEN** card holding three checkboxes: Radar,
Thermal, EO. Default all on.

**Semantics:** turning a sensor OFF hides its contribution from the
*other* panels. A sensor's own native view is unaffected.

**Filter logic** (`gui/static/js/main.js`, WS onmessage):
```js
const fusedForPanel = (panel) => fusedAll.filter(t => {
  const sensors = t.sensors || [];
  return sensors.some(s => s !== panel && _overlay[s]);
});
```
Radar (no late-fusion contribution yet) is gated by `_overlay.radar`
directly.
