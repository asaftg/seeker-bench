## 1. Late fusion: radar as third sensor

`FusionManager` now consumes `RadarTarget`s alongside EO/thermal
detections and produces `FusedTrack`s where `sensors` can include
`"radar"`.

- New `_observations_from_radar()` does cartesian → angular projection
  (`atan2(x,y)` for az, `atan2(z,√(x²+y²))` for el) with the radar
  extrinsic bias applied.
- Three-way cross-sensor association in `_tick`:
  1. EO ↔ thermal (existing; `XSENSOR_IOU=0.15`, class match required);
  2. radar attaches to existing camera candidates by IoU (class wildcard,
     more permissive `radar_iou_gate=0.05`);
  3. surviving radar obs become standalone `RADAR_TARGET` candidates.
- Class lock: a track born radar-only stays `RADAR_TARGET` until
  EO/thermal joins, then locks in the camera class. Once locked,
  radar can keep the lock alive but cannot overwrite the class.
- New enum value `TargetClass.RADAR_TARGET` and frontend mapping
  (`_clsLabel`) renders the row as **"RADAR TARGET"** with cyan styling.
- `FusionManager.set_extrinsic` extended to accept radar bias;
  `gui/app.py`'s `extrinsic_tune` handler now routes radar bias to
  BOTH `RadarManager` and `FusionManager` so they stay in lockstep.
- Coasting radar targets are skipped at the fusion observation step —
  conservative to avoid dragging cross-sensor locks around on
  Kalman-only positions.

## 2. Per-sensor decay (sensors_now without flicker)

Replaced the `sensors_ever` accumulator (which never decayed) with
a per-sensor miss counter so the published `sensors` list reflects
who is **currently** seeing the target, with a small grace window to
absorb 1–2 frame dropouts:

- Each track carries `sensor_misses: dict[str, int]`.
- On match: bump every sensor's miss, reset to 0 for sensors in the
  candidate, prune entries past `fusion.sensor_grace_ticks` (default
  5 ≈ 333 ms at 15 Hz).
- On miss tick: bump and prune.
- `_publish` skips tracks whose active-sensor set decayed to empty
  (track stays internally for re-acquire id stability, but doesn't
  draw a stale dashed projection).

Live trace example: radar joined thermal track #47 at t=78.9 s
(`('radar','thermal')`), radar dropped at t=79.4 s
(`('thermal',)` again, class still `vehicle`). The "2× THERMAL+RADAR"
sticky-pill bug from the user screenshot is gone.

## 3. Coasting radar overlay filter (now superseded — kept for context)

Initial fix: skip the EO/thermal projection (`bbox_thermal`,
`bbox_eo`) for coasting radar targets so they wouldn't accumulate
ghost boxes on the camera panels while the radar Kalman dead-reckons.
Superseded by §4 below — the entire raw-radar projection path was
removed shortly after.

## 4. Unified radar overlay: drop the cyan duplicate

After §1, two paths were drawing every radar target on the camera
panels: the original projection-overlay (cyan dashed `R#tid`) plus
the new fused-track projection (orange dashed `#fusedId RADAR_TARGET
← RADAR`). Removed the projection-overlay path entirely:

- `gui/sensor_bridge.py` no longer computes `bbox_thermal` /
  `bbox_eo` for radar targets.
- `gui/static/js/{thermal,eo}_view.js` drop the `drawRadarBox` loop.
- The radar PANEL itself is unchanged — `radar_view.js` still renders
  trails / TID / range / velocity from the same `radar.targets`
  payload (the bbox keys went away, the scalar fields stayed).
- The OVERLAY SCREEN "Radar" toggle keeps working through the
  source-centric `fusedForPanel()` filter — radar-only fused tracks
  vanish from EO/thermal when radar is off.

Net result: ONE box per real target on each panel — green if
multi-sensor confirmed, dashed class-coloured if single-sensor
projected.

## 5. Pre-existing bug fixed in passing

`Pass 3` of `_tick` (radar attach) had `used_c = [False] *
len(candidates)` sized **before** the loop, but the unmatched-radar
`else` branch appended to `candidates` mid-iteration. The next outer
iteration walked past `used_c`'s end and crashed the fusion tick.
Snapshotted the camera-candidate count up front. The crash had been
silently dropping fusion ticks via `_loop`'s try/except wrapper,
which is why the very first radar-fusion test showed empty `sensors`
lists on every track.
